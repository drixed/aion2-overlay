# AION 2 оверлей: ДПС-метр + таймеры — дизайн

Дата: 2026-10-07 · Регион: EU (глобальные сервера)

## Цель

Один оверлей поверх AION 2: ДПС группы и таймеры событий (полевые боссы, разломы, ивенты).
Главное требование — **всегда актуален**: после патчей игры парсер чинится без нашего участия,
программа обновляется сама.

## Решения

- **Основа — форк [RATmeter](https://github.com/Kuroukihime/AIon2-Dps-Meter)** (C# / .NET 10 / WPF, GPL-3.0).
  Самый активно поддерживаемый открытый метр для глобальных серверов: пассивный захват через Npcap,
  разбор протокола, ДПС группы, история боёв, встроенный обновлятор.
- **Свой разбор протокола не пишем.** Его поддерживает апстрим; мы только подтягиваем изменения.
- **Разбор списка полевых боссов** (пакет со временем респавна из карты игры) переносим из
  [cyberbadger6969/aion2-dps-meter](https://github.com/cyberbadger6969/aion2-dps-meter) (GPL-3.0, совместимо).
  Там же берём hex-образцы пакетов для тестов.
- Наш код — **GPL-3.0**, репозиторий публичный: `github.com/drixed/aion2-overlay`
  (форк RATmeter; эта папка `Desktop/AION2` становится его рабочей копией).

## Принцип «минимум правок в чужом коде»

Чем меньше мы трогаем файлы апстрима, тем реже конфликты при слиянии. Правила:

1. Всё своё — в новых файлах: отдельный проект `AionDpsMeter.Timers` + новые файлы в UI.
2. Новые обработчики пакетов — новые классы с `[PacketOpcode]`; RATmeter регистрирует их
   автоматически (сканирование сборки в `ServiceCollectionExtensions`).
3. Допустимые точечные правки апстрима (каждая — 1–5 строк, перечислены в одном месте, `FORK_CHANGES.md`):
   - URL обновлений в `UpdateCheckerService` → наш репозиторий;
   - регистрация модуля таймеров и окна таймеров в DI/старте приложения;
   - событие «сущность умерла» в обработчике смерти, если без него не обойтись
     (один опкод = один обработчик, второй на `EntityDeath` зарегистрировать нельзя).
4. Версию в `.csproj` не трогаем — её задаёт CI при сборке (см. ниже).

## Компоненты

### 1. Модуль таймеров (`AionDpsMeter.Timers`)

Чистая логика без UI, покрывается тестами.

- **FieldBossTracker** — полевые боссы, отдельно по каждому серверу.
  - Источник 1 (основной): пакет списка боссов карты — игра сама сообщает, кто жив и когда респавн.
    Приходит, когда открыта карта в игре.
  - Источник 2: смерть босса в поле зрения → отсчёт от момента смерти + известный интервал респавна.
  - Источник 3: ручная отметка «убит» (кнопка / хоткей) — если не видели ни карту, ни смерть.
  - Интервалы респавна: из списка игры, иначе выученные по наблюдениям, иначе из `schedule.json`.
- **ScheduleService** — события по расписанию (разломы, ивенты, сброс дня/недели).
  - Расписание — `schedule.json` в репозитории. При запуске программа скачивает свежую версию
    с GitHub (raw); при ошибке сети — последняя сохранённая копия, затем встроенная в сборку.
  - Формат: событие = имя, тип (`fixed` — список времён суток / дней недели, `interval` — старт + период),
    часовой пояс сервера, длительность. Время показывается в локальном поясе пользователя.
  - Начальные данные: разломы каждые 3 часа — **время для EU сверяется в игре при первом запуске**,
    до этого помечено «не проверено».
- **AlertService** — за N минут до события (настраивается, по умолчанию 5 для боссов, 2 для разломов):
  звук + всплывающая строка в оверлее. Каждое событие оповещает один раз.
- Состояние (времена смертей, выученные интервалы) сохраняется в JSON в папке настроек — переживает перезапуск.

### 2. Окно таймеров (UI)

- Отдельное окно рядом с ДПС-оверлеем RATmeter, в его же стиле: прозрачное, поверх игры, перетаскивается.
- Режим «клики насквозь» (окно не перехватывает мышь) — переключается хоткеем, как у ДПС-окна.
- Список: ближайшие события по времени; строка = иконка типа, имя, зона, обратный отсчёт.
  Живой босс — «жив с ЧЧ:ММ». Неизвестное — «?».
- Фильтр: какие типы событий показывать; можно скрыть отдельные события.
- Работает в режиме окна без рамки (borderless) — как и ДПС-оверлей апстрима.

### 3. Автообновление

- **GitHub Actions, раз в сутки + вручную:**
  1. `git fetch upstream` → слияние `upstream/main` в наш `main`.
  2. Конфликт → задача падает и создаёт issue «Конфликт с апстримом» со списком файлов. Релиз не выходит.
  3. Сборка + тесты. Падение → issue, релиз не выходит.
  4. Есть изменения с прошлого релиза → `dotnet publish` (self-contained, один zip), релиз на GitHub.
- **Версия:** `ГГГГ.ММДД.N` (N — номер запуска CI), задаётся при сборке через `-p:Version=…`.
  Всегда больше версий апстрима (1.x), сравнение в `UpdateCheckerService` работает без изменений.
- **В программе:** встроенный обновлятор RATmeter, указывающий на релизы нашего репозитория.
- Правка `schedule.json` релиза не требует — программа подхватывает её при следующем запуске.

## Поток данных

```
Npcap → [апстрим: захват → TCP → кадры → опкоды] ─┬─ обработчики апстрима → ДПС-оверлей
                                                  └─ наши обработчики (список боссов, смерть босса)
                                                          ↓
schedule.json (GitHub → кэш → встроенный) → ScheduleService ─┐
                                    FieldBossTracker ────────┴→ AlertService → окно таймеров
```

## Ошибки и деградация

- Пакет списка боссов не распознан (протокол сменился) → логируем, таймеры боссов работают на смертях
  и ручных отметках; ДПС не страдает. Исключения наших обработчиков не роняют конвейер апстрима.
- Нет сети → кэш расписания / встроенное расписание; обновление пропускается молча.
- Сервер не определён → боссы показываются без привязки к серверу с пометкой.

## Тестирование

- Модульные тесты (xUnit) для `AionDpsMeter.Timers`: расчёт следующего события по расписанию
  (часовые пояса, переход через полночь, дни недели), трекер боссов (список игры важнее наблюдений,
  выученный интервал, ручная отметка, по-серверно), однократность оповещений.
- Разбор пакета списка боссов — на hex-образцах из cyberbadger.
- CI гоняет тесты при каждом слиянии апстрима.
- Проверка в игре — делает пользователь (у разработчика нет доступа к игре); логи пишутся в файл
  для разбора проблем.

## Вне рамок

- Собственный разбор протокола, сайт, облако, рейтинги, OCR.
- Другие регионы (KR/TW) — не тестируются, но расписание и опкоды от апстрима не мешают их добавить.
